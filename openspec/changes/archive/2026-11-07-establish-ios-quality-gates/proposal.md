# Proposal

## Why

После реорганизации iOS-кода проект имеет воспроизводимый формат и E2E-набор, но проверки выполняются вручную, а правила для единственного разработчика и агентов не закреплены в репозитории. Из-за этого следующий change может незаметно нарушить структуру файлов, формат или пользовательские сценарии.

## What Changes

- Добавить GitHub Actions для проверок OpenSpec, формата Swift, тестов и сборки iOS; запускать короткий E2E `Smoke` для PR, а полный `Full` — по явному запросу в PR и после интеграции в основную ветку.
- Закрепить исполняемые локальные команды и версии инструментов, чтобы агент и CI проверяли код одинаково; сохранять диагностический `xcresult` при провале UI-тестов.
- Ввести небольшой набор правил SwiftLint, дополняющих `swift-format`, с локальной командой и проверкой в CI; выбрать правила после оценки нарушений в существующем коде, без массовых подавлений.
- Добавить в репозиторий `AGENTS.md` с правилами структуры, ответственности файлов, расположения тестов, границ домена, обработки ошибок и минимального доказательства проверки перед коммитом; дополнить краткий чеклист ревью для работы одного разработчика с агентами.
- Не менять поведение приложения, публичные API, схему SQLite и продуктовые specs. Новые продуктовые функции, backend CI, TestFlight, обязательные локальные hooks и блокирующие настройки защиты ветки остаются для отдельных changes.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Это инструменты разработки и инструкции агентам без изменения пользовательских требований; `skip_specs: true` задан в `.openspec.yaml`.

## Impact

Новые файлы в `.github/workflows/`, конфигурация SwiftLint, локальный скрипт или единая команда проверок, корневой `AGENTS.md` и документация разработки. Потребуется доступ GitHub Actions к macOS runner с совместимым Xcode; приватный репозиторий расходует включённый лимит Actions. Runtime-зависимости приложения и данные пользователей не затрагиваются.
