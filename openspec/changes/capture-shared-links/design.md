# Design

## Context

См. [proposal.md](proposal.md). Сейчас `MemoryKind` и `Original` знают только текст и изображение; начальная миграция `MemoryRepository` не содержит поля URL, поиск использует FTS подтверждённого текста, а Share Extension выбирает только `UTType.image`. Карточка и список явно обрабатывают два существующих типа. Архитектурные границы заданы ADR-001, ADR-002, ADR-003 и ADR-009.

## Goals / Non-Goals

**Goals:** Сохранить адрес как оригинал в том же локальном хранилище, не изменяя записи прежних типов; сохранить существующее поведение Share для изображения; сделать полный путь ссылки проверяемым без сети.

**Non-Goals:** Заголовки и снимки веб-страниц, фоновая загрузка, AI, предпросмотр с сетевым запросом, универсальный импорт текста из Share Sheet, экспорт и восстановление.

## Decisions

### Отдельный тип оригинала и добавочная миграция

Добавить `MemoryKind.link`, `Original.link(url: String)` и nullable `original_url` в `memory_items` через новую именованную миграцию. Для ссылки `original_path` и `original_text` остаются пустыми; исходный URL хранится как строка, полученная от Share, и не подменяется заголовком страницы. Загрузка записи и отображение переключаются по всем трём типам явно. Это сохраняет разделение оригинала и подтверждённых данных по ADR-002 и ADR-003. Альтернатива — хранить URL как текстовую заметку — смешала бы два разных оригинала и усложнила открытие страницы.

### Захват одного URL без сетевой обработки

В `Info.plist` расширения объявить поддержку одного web URL через [системный ключ Apple](https://developer.apple.com/documentation/bundleresources/information-property-list/nsextension/nsextensionattributes/nsextensionactivationrule/nsextensionactivationsupportsweburlwithmaxcount) вместе с текущим изображением. Обработчик Share сначала сохраняет существующий путь изображения, а для URL загружает значение из `NSItemProvider` и принимает только адрес с `http`/`https` и непустым host. Сохранение идёт через отдельную операцию репозитория и подтверждается только после commit. Повтор того же URL использует стабильный `captureID`, производный от адреса, аналогично текущему хешу изображения. Это не требует разрешения на сеть и следует ADR-001 и ADR-002. Альтернатива — загружать страницу ради названия — нарушила бы офлайн сценарий и расширила бы границу данных.

### Локальный поиск и явное открытие

Существующий FTS подтверждённого текста оставить неизменным. Поиск дополняется параметризованным сопоставлением исходного URL без учёта регистра с экранированием шаблонных символов; результаты объединяются без дублей и сортируются как текущие записи. Для небольшого локального набора ссылок это проще отдельного FTS индекса URL; при измеренном росте данных можно добавить индекс отдельным change. Список показывает адрес как запасной заголовок. Карточка показывает исходный адрес и системное действие открытия только по нажатию пользователя, без автоматического обращения к странице.

## Risks / Trade-offs

- Разные приложения могут передавать URL разными представлениями `NSItemProvider` → покрыть URL объект и строковое представление в адаптере, а реальный Share Sheet проверить UI тестом.
- Поиск URL через сопоставление подстроки имеет линейную стоимость → оставить для MVP, измерить на большем наборе перед оптимизацией.
- Одинаковый URL, переданный повторно, даст одну запись → это согласовано с текущим захватом изображений по содержимому; отдельные намерения для одного адреса потребуют будущего решения.
- Старая версия приложения не понимает `kind=link` после добавления ссылок → не откатывать бинарник на старую версию с той же базой; до выпуска проверить миграцию существующих данных.

## Migration Plan

1. Добавить nullable колонку `original_url` отдельной миграцией; текущие текстовые и графические записи сохраняются без преобразования.
2. В том же выпуске добавить чтение нового типа, запись, Share UI и карточку. Прогнать миграцию на базе предыдущей версии и регрессию четырёх текущих E2E сценариев.
3. При неудаче до выпуска вернуть код; после сохранения ссылок старый бинарник с существующей базой не поддерживается.
