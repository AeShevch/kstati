# Design

## Context

Ежедневник хранит гражданскую дату и разделяет задачи и события. Напоминания используют локальное хранилище по ADR-002 и системный интерфейс iOS по ADR-001. Работа с уведомлениями отделяется от домена согласно ADR-003.

## Goals / Non-Goals

**Goals:** Проверяемый путь от ручного включения до регистрации, изменения и отмены уведомления.

**Non-Goals:** Геолокация, повторения, серверные уведомления и гарантии доставки в точную минуту.

## Decisions

- Хранить выбранный момент в SQLite рядом с задачей или событием через добавочную миграцию. При выборе времени интерпретировать дату плана в текущем часовом поясе и фиксировать полученный момент. Это сохраняет момент при поездке. Несуществующее местное время при переходе часов отклонять.
- Использовать системный идентификатор из ID плана. Через один адаптер проверять разрешение, регистрировать и заменять запрос, отменять ожидающий запрос. Для экрана блокировки использовать нейтральный текст без содержимого записи.
- Сериализовать изменения напоминаний. Перенос и выполнение очищают настройку в той же транзакции, что меняет план, после чего адаптер отменяет запрос. При открытии приложения сверять настройки с системными запросами, удалять устаревшие запросы и восстанавливать отсутствующие будущие только при действующем разрешении. Пока система не подтвердила регистрацию, UI не показывает напоминание активным.
- При переносе выключать напоминание и показывать это в редакторе. Автоматический перенос мог бы назначить неожиданное время.

## Risks / Trade-offs

- SQLite и очередь iOS меняются раздельно → сверка при следующем запуске исправляет расхождения после прерывания операции. Между прерыванием и следующим запуском устаревший запрос может остаться в очереди.
- iOS может задержать или скрыть уведомление → UI сообщает о регистрации, а не обещает доставку.
