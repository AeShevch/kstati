# Design

## Context

Память хранится локально в SQLite. Архитектура выделяет Task и CalendarEvent как отдельные сущности. Применяются ADR-001, ADR-002 и ADR-003.

## Goals / Non-Goals

**Goals:** Проверить полный путь от исходной карточки до плана дня.

**Non-Goals:** Время суток, повторы, внешние календари, уведомления и экспорт сущностей ежедневника.

## Decisions

- Добавочная миграция создаёт таблицы задач и событий. Оба типа имеют собственный идентификатор и необязательную ссылку на запись с `ON DELETE SET NULL`. Раздельные таблицы выражают разные инварианты даты и выполнения. Исходный материал остаётся в памяти.
- Дата хранится как гражданский день по григорианскому календарю. «Сегодня» вычисляет его в текущем часовом поясе устройства. UTC-момент мог бы сдвинуть дату при поездке. Список обновляется при возвращении приложения на экран и смене дня.
- Переход в «Сегодня» размещается в навигации «Памяти». С экрана «Сегодня» доступен список «Все планы», чтобы записи вне текущего дня и без источника можно было найти. В карточке можно создать план и изменить дату связанных элементов. Решение о главном экране остаётся открытым до отдельного изменения навигации.

## Risks / Trade-offs

- Граница дня и смена часового пояса → проверить переход через полночь и сравнение гражданских дат при разных поясах.
- Миграция действующей базы → открыть старую базу после миграции и проверить записи, группы и ссылки.
