# Spec Delta

## Purpose

Пользователь контролирует передачу текста и решает, какие предложения анализа станут планами.

## ADDED Requirements

### Requirement: Согласие на конкретный текст
Приложение SHALL отправлять только показанный пользователю текст текущей записи после явного подтверждения запроса. Каждый повтор SHALL требовать нового подтверждения.

#### Scenario: Отмена
- **WHEN** пользователь закрывает предварительный просмотр или отменяет отправку
- **THEN** запрос не выполняется

#### Scenario: Подтверждение
- **WHEN** пользователь подтверждает отправку показанного текста
- **THEN** сервис получает этот текст без вложений и других записей

### Requirement: Проверка предложения
Результат анализа SHALL оставаться предложением до явного сохранения задачи или события пользователем.

#### Scenario: Выбор результата
- **WHEN** пользователь проверяет и подтверждает одно предложение
- **THEN** в ежедневнике создаётся выбранный план со ссылкой на запись

#### Scenario: Сбой
- **WHEN** сеть недоступна или ответ не соответствует контракту
- **THEN** приложение сообщает об ошибке, сохраняя запись и существующие планы

### Requirement: Проверка в локальной среде
Сервис разработки SHALL возвращать структурированные предложения через тестовый адаптер и SHALL исключать пользовательский текст из журналов.

#### Scenario: Локальный сквозной тест
- **WHEN** тестовая сборка отправляет синтетическую запись
- **THEN** приложение получает воспроизводимый результат без вызова облачного провайдера
